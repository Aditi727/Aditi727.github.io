AI Event-Driven Customer Operations

Problem: Synchronous integrations can lose work, repeat side effects or block callers when AI and CRM services are slow or unavailable.

Solution: A Fastify API accepts events quickly while a RabbitMQ worker performs structured analysis, human-review routing, retry recovery and protected replay with persistent SQLite state.

  • Separate API and worker processes with correlation IDs
  • Three TTL retry tiers, DLQ and atomic replay
  • Idempotency, worker leases and status history
  • Low-confidence human-review queue
  • Docker Compose acceptance with real RabbitMQ

Verification boundary: Demo Mode passed end to end; live OpenAI and HubSpot validation remains pending credentials.

Architecture REST API → RabbitMQ → worker → review/retry/DLQ → persistent state
